## 3. 中标信号识别与升级链

新闻正文按信号强度分三级：

1. **强信号（直接候选）**：中标、中标候选人、成交、正式授标、合同签订、战略合作协议签署（含具体项目名）
2. **弱信号（项目线索）**：上线、正式运行、落地、交付、签约合作、助力XX医院/卫健委（无项目编号）
3. **无信号**：产品发布、白皮书、获奖、峰会

升级链（写入台账的必要条件）：

```
厂商新闻(L1-L4) → 提取线索{项目名, 采购人, 时间, 地域, 产品线}
  → 反查A类采购人公告（31省双入口/央采，匹配 采购人+项目名+时间窗±90天）
  → 命中：线索升级为中标证据，双来源记录（corroborated需核验人+核验日期）
  → 未命中：保留为 pending 线索，notes注明"仅厂商自宣"
```

同稿多平台转载（官网→公众号→媒体）**不计独立证据**，只保留首发URL。

## 4. 技术形态与抓取策略

| 形态 | 来源示例 | 策略 |
|---|---|---|
| 静态HTML列表 | 讯飞医疗news、cudt新闻（待验证） | 默认research流水线，max_pages小预算起步 |
| JS渲染/SPA | 蚂蚁数科、天翼云、腾讯云 | 先探测页面内JSON接口；无接口再评估browser（需显式参数） |
| 检索页跳转 | 公众号（搜狗微信） | 人工/半自动按期检索，当日转存正文 |
| PDF直链 | 披露易、巨潮公告 | 直接下载存原文+页码，进入evidence流程 |

统一约束：robots拒绝/付费墙即停；域名白名单逐站登记，不为便利放开任意域名；每来源独立失败处置，不做整站。

## 5. 任务划分（对应 run-local.ps1 规范）

- `T1`：L2静态三站试采（讯飞医疗、联通数科、联通云）——新task_id + 新source_config（把 cudt、cucloud、tech.antfin.com 追加进 C 类来源配置），先 `--dry-run` 后实跑，max_pages=2起步
- `T2`：L5披露通道——巨潮4家按"中标"关键词全文检索计划（plan provider，离线生成检索式）；披露易2家按代码列举公告标题
- `T3`：L2动态三站接口探测（腾讯云、天翼云、蚂蚁数科）——只探测不批量抓取，探测结果回写台账 rules 的 references
- `T4`：L4公众号——人工列monitor清单+每月1次半自动检索（不适合自动流水线，走独立轻流程）

每个T独立task_id；T1-T3完成前不产出任何"中标统计"。
