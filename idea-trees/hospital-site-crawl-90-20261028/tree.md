## 节点

- **需求** `need`：按爬虫任务表已定位的90个官网入口，采集2024年1月1日至2026年10月28日医院官网发布的医疗数字化招标采购信息，回填任务表并保留原文证据。
  - **范围** `scope`：仅采医院官网来源：90条栏目采集任务（89个本院/院区官网＋1个中国人民解放军总医院总院采购平台），关联104条机构记录；批次P0 1条、P1 62条、P2 26条、P3 1条。官网栏目发现（P4）428家待定位机构不纳入本轮。
    - **边界** `excluded`：不采政府采购平台（中央、中国政府采购网、北京市、河北、雄安）作为本轮成果；平台公告只作官网缺失时的线索，不并入官网采集数。合作医院、院区、总院共用入口按任务表关联医院ID核验归属，不按名称自动归并。
  - **入口清单** `entrances`：已从任务表导出90条入口：[entrances.csv](entrances.csv)与[entrances.json](entrances.json)，含任务ID、批次、医院、关联医院ID、栏目类型、栏目路径、入口网址、日期范围与执行状态；89个唯一域名，5条任务一网多机构（301总院覆盖11家）。
  - **方法** `method`：沿用北医三院案例：入口核验 → 栏目列表及分页 → 详情正文 → 内层采购明细 → 附件 → D1-D5数字化判定 → 采购人与院区核验 → 公告与项目关联 → 回填任务表并保存原文。
    - **阶段0入口核验** `phase0`：已对90个入口做一次只读核验（单次GET＋每域名一次robots）：78个可读、7个需JS渲染或站点维护、3个入口404（丰台中西医结合、世纪坛OA、大兴中西医结合）、2个不可达（北京按摩医院、望京医院，代理502且直连超时）。结果见[entry_probe.csv](probe/entry_probe.csv)。
      - **核验结果** `phase0_result`：可读78条可直接进入采集；7条需适配（上地医院、延庆区医院维护中、石景山医院#路由、顺义中医院disclosure、通用航天/purchase、安定医院招采平台登录页、潞河医院）；3条404需重新定位入口；2条不可达标记待补。三类失败分别记录，未合并为'无采购'。
    - **阶段1P0试采** `phase1`：北医三院（C0057）试采已完成：翻页44页、列表528条、2024年以来518条（2024年90条、2025年128条、2026年300条），关键词候选72条并保存72份详情正文，失败0。
      - **试采结果** `phase1_result`：518条日期内条目、72条关键词候选（D4系统类53、D1基础设施15、D5安全9、D2数据7、D3后勤1，可多计）；其中9条为'耗材试用信息'等信息类误收，另有锅炉阀门、电梯报警等边界条目，均需正文复核后定性；机房空调维保2条按设备维保另议。复跑修正了两处分页/URL拼接错误：真实分页为zbcg/90至40共52页、详情须urljoin。
    - **阶段2P1批量** `phase2`：77个可读站点批量采集完成（C0057已单独试采）：324个列表页、4017条公告条目、2024年以来2854条、标题关键词候选951条、保存候选详情921份、失败7份。脚本 scripts/hospital_batch_crawl.py，每站单线程1请求/秒、6站并行。
      - **执行计划** `next_phase2`：已执行：2026-10-28批采，结果见 [batch_summary.csv](../../outputs/hospital-site-crawl-90-20261028/batch-20261028/batch_summary.csv)。
      - **批采结果** `phase2_result`：全批次：4017条/2854条2024以来/951候选/921详情。候选最多：北大第六49、肛肠44、整形外科43、天坛42、朝阳40。4站需JS渲染（301总院平台、门头沟、北大国际、广安门南区）；13站列表页无日期（54doctor CMS），日期在详情正文，待下一阶段补齐归位；7份详情失败已在站点summary记录原因。
    - **阶段3P2P3补采** `phase3`：P2 26条公开混合栏目需在通知公告中筛采购类条目；P3 1条301总院采购平台按11家医疗区机构核对采购人与项目地点。
      - **执行计划** `next_phase3`：下一阶段：①正文级数字化判定（读取921+72份候选详情，按采购标的定案，剔除耗材误收）；②13个无日期站从详情正文提取发布日期归位；③4个JS渲染站用浏览器通道补采；④12个404/不可达入口重新定位；⑤按任务表回填发现公告数/详情成功数/数字化纳入数。
        - **模板化整理** `phase3_extract`：按用户模板（项目名称/产品/招标单位/客户标签/中标单位/运营商类型/中标金额万元/场景/时间）从1096条候选详情抽取：保留775条数字化项目（2024以来738条+37条无日期），排除249条非数字化（工程改造125/医用设备86/无信号38）。抽得中标单位81、明确金额50条；中标1家运营商（中国电信翼康，北大第一医院AI预测模型）。脚本 scripts/hospital_projects_extract.py；交付 outputs/.../projects_table/ 与 沟通目录xlsx/csv。
          - **抽取口径** `extract_rules`：口径：①金额只取成交/中标金额，预算/限价/控制价黑名单剔除，元自动折万元；②中标单位需显式中标/成交短语或结果公示上下文中紧跟的名称，医院/大学/代理机构/采购人排除，废标作废终止清空；③场景沿用五分类（IT基础设施/临床运营系统/临床数据/智慧后勤/网络安全）；④客户标签=区域·等级（来自593机构表）；⑤运营商=名称以移动/电信/联通/铁塔/广电开头或含中移/翼康/天翼；⑥37条日期缺失（54doctor站列表无日期且正文无发布时间），保留并备注。
    - **阶段4回填归档** `phase4`：按任务ID回填执行状态、最近采集时间、发现公告数、详情成功数、数字化纳入数、已覆盖日期范围、失败原因与回填结果位置；另出汇总台账、按院证据包与核验记录。
  - **采集规则** `rules`：数字化按D1基础设施、D2临床数据、D3智慧后勤、D4临床运营系统、D5网络安全五类判定；普通设备固件、实物柜外存储不纳入；预算、成交、合同、单价、年费分列不互加；验证码与robots限制记录为缺口，不绕过。
    - **关联口径** `rules-dedup`：公告按规范网址与正文标识去重，一个公告在多栏目出现时保留全部来源；采购、变更、结果分列不同公告；项目按采购人、项目编号、分包关联，同名年度项目不直接合并。
  - **交付** `outputs`：①回填后的任务表副本（新增attempt不改原表）；②按院原文与元数据包；③数字化采购汇总台账（含证据链接）；④入口核验与失败记录；⑤本树节点与统计更新。
  - **已知缺口** `gaps`：89条任务标注待入口核验，入口可能已迁移或栏目改版；医院站点常见JS渲染、附件权限、验证码与超时；一网多机构需按采购人区分，不能把总院项目计入院区。
  - **风险控制** `risks`：单站限速并识别robots；单站失败不影响批次其它站；原始页面与解析结果分开保存；回填前先备份任务表；解析不确定的条目进待核表，不硬判纳入或排除。
