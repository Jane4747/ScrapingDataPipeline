爬虫能力与任务分工清单（2026-10-27）

适用范围
本清单区分原项目能力、当前本地 MCP 已接入的能力和已完成的验证。以后执行前先查询 crawler_status，不能仅根据本清单的历史状态判断后端已经可用。
目前 fetch_page 和 render_page 无需后端模型，可读取网页并由 Codex 整理。browser-use、Skyvern、ScrapeGraphAI 已安装并验证浏览器基础能力；自主决策和智能提取仍待 DeepSeek V4.1 Flash 配置后验收。Firecrawl 尚未启动，等待手动重启后完成容器安装。

1. browser-use：灵活的网页交互
适合：拿到数据之前需要搜索、点击、翻页、展开、滚动、切换标签页的任务。
主要能力：
- 在指定网站输入关键词并操作搜索结果、筛选项和分页。
- 进入列表详情，提取正文、表格、链接等内容。
- 依据页面当前状态决定下一步操作，完成跨多个页面的采集。
- 在任务中处理公开附件下载，保存执行历史。
- 可按要求返回文字或 JSON；指定输出结构后进行结构校验。
任务示例：在某医院采购栏目检索指定设备，逐页进入公告详情，提取标题、发布日期、采购人和原文网址。
当前接入：自然语言目标＋起始 URL 清单＋操作步数和时限。历史保存已接入；重放、上传文件等没有单独的统一工具。
边界：每个任务使用独立浏览器资料目录，不自动继承日常 Chrome 登录态。需要登录的任务先配置凭据/会话。模型驱动的交互尚待验收。

2. Skyvern：明确步骤的网页流程
适合：同一个站点里需要按固定步骤执行检索、筛选、打开详情、提取或下载的任务。
主要能力：
- 将检索、条件选择、页面导航和信息提取串成多步骤任务。
- 按指定字段提取结果，目标中可要求检查关键字段或页面状态。
- 原项目支持表单交互、登录、文件下载及更完整的工作流能力；实际使用前须接好相应凭据并做流程验收。
任务示例：进入某省采购网站，输入关键词，选择公告类型和年份，打开结果详情，提取采购人、预算、日期和附件链接。
当前接入：一次一个起始 URL，通过 run_task 执行自然语言多步骤任务；内存 SQLite，专用本地浏览器。
边界：当前没有开放命名工作流管理、工作流调度或 Web 管理界面。任务结果落盘，但内存数据库不承担跨任务业务状态保存。登录、验证码和视觉识别不列为当前已验收能力。

3. ScrapeGraphAI：按字段理解和提取网页
适合：网址已知、页面排版不统一，但希望提取出相同字段的任务。
主要能力：
- 单个 URL 的自然语言字段提取。
- 对多个已知 URL 使用同一字段要求提取并汇总。
- 处理不同网页布局中表达方式不同的字段，输出结构化 JSON。
- 可给出 JSON Schema，检查字段类型、必填项等结构约束。
任务示例：从一组企业或医院详情页提取机构名称、项目名称、产品名称、发布日期、原文依据与来源链接，未知值留空。
当前接入：SmartScraperGraph 和 SmartScraperMultiGraph；输入 URL 清单、提取要求和可选输出结构。
边界：当前入口没有接入 SearchGraph、脚本生成、音频生成或本地文档任务。复杂按钮交互交给 browser-use/Skyvern。扫描 PDF、图片和 OCR 需要另接专门工具。结构校验不等于字段事实已经核实。

4. Firecrawl：站点链接发现与批量原文采集
适合：从一个站点入口发现链接，批量取得页面正文，建立后续分析或知识库的原始资料。
当前规划接口：
- firecrawl_map：发现站点 URL。
- start_crawl(engine=firecrawl)：从一个起始 URL 批量抓取，设置页数上限。
- 返回页面 Markdown、来源链接及采集结果。
任务示例：从某政策库或产品文档站点入口抓取最多 100 页，随后由 Codex/ScrapeGraphAI 筛选主题并提取字段。
边界：当前本地接口只接 map/crawl，不含厂商云 Agent、搜索、监控等全部能力。任务里的自然语言不会自动转换为主题/年份/栏目过滤规则；精确筛选还需额外规则或后处理。当前不接受结构化输出 schema。复杂交互另用浏览器智能体。
状态：WSL 与必要 Windows 功能已装，Ubuntu 镜像已准备；尚需用户手动重启后完成 Docker Engine、容器启动和真实抓取验收。

5. 两个现在即可使用的基础工具
fetch_page：读取普通 HTML，返回标题、正文和链接，可选 CSS 区域；不执行 JavaScript。
render_page：本地 Chrome 渲染后读取正文和链接，保存 HTML、截图；不自动点击、筛选、翻页或无限滚动。
简单网页优先直接读取；需要 JavaScript 才出现内容的页面先渲染。两者的内容都可由 Codex 进一步整理。

6. 调度与交付
当前默认同时一个任务，默认时限 15 分钟。交互任务默认最多 30 步，Firecrawl 默认 20 页，可按任务调整。max_pages 只约束 Firecrawl 页数及输入 URL 数，不能当作 browser-use/Skyvern 的硬性访问页数上限。
结果和日志保存在 E:\CAICTBigData\coding\local-crawlers\runs。基础产物为 JSON、正文或 Markdown；CSV/Excel 由 Codex 后续汇总。
尚未配置周期调度、代理池、通用 OCR、跨任务登录态复用或验证码处理。视觉能力须确认模型兼容后再启用。
本组件是独立 MCP 后端，尚未并入父项目版本1研究任务协议；正式研究仍须遵守来源范围、证据留存和核验要求。

安排任务时提供
目标；入口网址或来源清单；站点/栏目/关键词/时间范围；需要的字段；页数或记录数、操作步数和时间预算；输出格式；是否保留原文及附件。缺失字段留空，结果保留来源链接。
