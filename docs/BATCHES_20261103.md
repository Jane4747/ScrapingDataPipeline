# 2026-11-03 批次工具

这组工具来自六省/全国医院招采续采、公共资源更新和央采续采工作区。保留可复用的采集、离线提取、证据复核与回归测试；原始网页、断点、实际医院名录、手工回填结果、报告生成程序及浏览器缓存不随代码发布。

`scripts/batches_20261103/source-manifest.json` 记录原脚本 SHA256。`source_sha256` 标识迁移前来源，`published_sha256` 校验当前发布副本；新副本已改为仓库相对路径或显式输入，两种摘要必须按对应文件比较。`published_files` 另列全部发布代码、测试和模板的当前摘要（不包含清单自身）。医院核心选用全国批次版本，避免再提交六省版本的重复实现。

## 安装与目录

在仓库根目录执行，Python 3.10+：

```powershell
python -m pip install -r scripts/batches_20261103/requirements.txt
```

医院和央采工具使用普通 HTTP 与本地解析；`public_resources/` 实际运行还需要 Playwright 可用浏览器。已有 Chrome 可通过 `--browser-executable` 指定；需要 Playwright Chromium 时由使用者显式执行 `python -m playwright install chromium`。安装步骤需要联网，以下离线校验无需联网。

| 子目录 | 入口及用途 |
|---|---|
| `hospitals/` | `collector.py` 单院有界采集；`run_batch.py` 按域名串行、跨域并行调度；`select_resume.py` 从现有证据选择续采队列 |
| `hospitals/` | `consolidate.py` 合并页面和名录覆盖记录；`extractor.py` 离线提取；`cached_extractor.py` 按源码/原文指纹缓存；`apply_verified_reviews.py` 校验人工引用后应用修订 |
| `public_resources/` | `guarded_run.py` 包装有限采集快照，拦截日期窗口失效、非零总数空页、重复分页与访问挑战 |
| `zycg/` | `continue_zycg.py` 按月和中标/成交类型续采，记录分页完整性证据与断点 |
| `examples/` | 假医院、保留示例域名的输入模板与空复核数组，不是真实采集结果 |

## 医院输入及运行

三个输入文件放在同一个新任务目录。`entrances.json` 包含 `entrances` 数组，每项有唯一 `task_id`、`hospital`、`hospital_ids`、`hospital_entities`、`url`、`province`、`entry_kind` 和 `entrance_verified`。`roster.json` 为数组，保留每家医院的 `entity` 与对应 `task_id`；没有入口的医院也要保留，`task_id` 为空并填写 `source` 和 `entity.source_row`。`contract.json` 记录 `since`、`until` 和域名间隔 `min_delay_seconds`。

先复制模板、填入已确认的真实范围。使用新目录隔离任务；同一目录续采不能改变医院入口或日期合同。

```powershell
$env:HOSPITAL_BATCH_RUN = Join-Path $PWD 'outputs/hospital-demo-20261103'
New-Item -ItemType Directory -Force $env:HOSPITAL_BATCH_RUN | Out-Null
Copy-Item scripts/batches_20261103/examples/entrances.json $env:HOSPITAL_BATCH_RUN
Copy-Item scripts/batches_20261103/examples/roster.json $env:HOSPITAL_BATCH_RUN
Copy-Item scripts/batches_20261103/examples/contract.json $env:HOSPITAL_BATCH_RUN

# 模板验证不联网、不写采集结果。真实采集前替换示例医院和网址。
python scripts/batches_20261103/hospitals/collector.py --site S00001 --entrances "$env:HOSPITAL_BATCH_RUN/entrances.json" --output $env:HOSPITAL_BATCH_RUN --since 2024-01-01 --until 2026-11-03 --scope digital --dry-run

# 以下命令实际联网；需先完成输入核对。
python scripts/batches_20261103/hospitals/run_batch.py --wave first --workers 4 --seconds 180 --list-pages 12 --details 100

# 离线选择队列，然后只续采已发现的数字化标题。
python scripts/batches_20261103/hospitals/select_resume.py --details-only --digital-titles-only
python scripts/batches_20261103/hospitals/run_batch.py --wave continuation --ids "$env:HOSPITAL_BATCH_RUN/continuation-ids.json" --details-only --digital-titles-only

# 合并及提取完全离线。
python scripts/batches_20261103/hospitals/consolidate.py
python scripts/batches_20261103/hospitals/cached_extractor.py --cache-dir "$env:HOSPITAL_BATCH_RUN/extract-cache" --pages "$env:HOSPITAL_BATCH_RUN/extraction-pages.json" --coverage "$env:HOSPITAL_BATCH_RUN/coverage.json" --output-dir "$env:HOSPITAL_BATCH_RUN/delivery" --since 2024-01-01 --until 2026-11-03 --scope digital --workers 1
```

`HOSPITAL_BATCH_RUN` 默认指向仓库 `outputs/hospital-batch-20261103`；设置它可以隔离任何批次。可选 `HOSPITAL_LEGACY_ARCHIVE` 指向旧医院原文归档，用于本地证据复用，不存在时不会构造历史结果。单院入口接受独立 `--output`，批次调度采用 `contract.json` 的日期。

每站输出 `sites/<task_id>/pages.json`、列表和详情原文、`listing_state.json`、`discovered_items.json`、进度与缺口；全局保留调度回执。提取输出 `records.json`、`rows.csv`、`excluded.json`、`coverage.json`、`summary.json`、`columns.json` 和 `dedup-evidence.json`。列定义以 `extractor.COLUMNS` 为准，包含公告日期/网址、采购主体、产品、供应商、万元金额、资格要求、医院身份、原文 SHA256 和原文路径。

缺失日期、主体或原文证据进入排除/待核结果。`--digital-titles-only` 会保留非数字化标题未抓取的缺口，`--details-only` 保留未遍历列表缺口。`coverage_complete=false` 或 `status=partial` 不能解释为完整覆盖；没有公告不等于没有采购项目。

人工修订用 `apply_verified_reviews.py --pages ... --output-dir ... --date-reviews ... --field-reviews ... --buyer-reviews ...`，三个复核文件均为 JSON 数组，无对应修订时传 `examples/empty-reviews.json`。先查看回执，加 `--apply` 才写回交付。复核记录须包含原文 SHA256、URL 与真实引用，源码中的校验和回归例子说明字段结构；修订不能凭空补日期或采购人。

## 公共资源采集保护

```powershell
python scripts/batches_20261103/public_resources/guarded_run.py --start 2026-01-01 --end 2026-11-03 --output outputs/ggzy-demo --keywords 医院 --max-api-calls 10 --max-details 20 --dry-run
# 实际执行时去掉 --dry-run；已有同一任务用 --resume。
```

可用 `--stage discover/details/reparse` 分开处理。`reparse` 重读本地详情；`discover/details/all` 会联网。默认保留 TLS 检查；访问挑战后停止后续列表与详情请求。保护器不会解验证码或把过滤无效的结果计作完成。独立快照保留 11 月 3 日对访问次数预算的修订，避免静默覆盖仓库主采集器；后续合并应同步其测试与来源记录。输出包括 `state.json`、原始列表/详情、提取记录、失败与覆盖情况，以命令回执为准。

## 央采中标/成交续采

```powershell
# 准备新的可恢复任务，验证期间不联网，但会创建计划和断点。
python scripts/batches_20261103/zycg/continue_zycg.py --output outputs/zycg-demo --start 2024-01-01 --end 2026-11-03 --validate-only
# 后续执行沿用同一输出目录与日期。
python scripts/batches_20261103/zycg/continue_zycg.py --output outputs/zycg-demo --start 2024-01-01 --end 2026-11-03 --resume --delay 8
```

可重复指定 `--baseline <JSON>` 读取已有 `records` 或明细数组，`--cache-root <目录>` 读取详情和分页 HTML。默认无基线/缓存即可准备；不隐式读取某台机器的旧交付物。列表缓存必须匹配查询日期、公告类型、分页连续性和官网声明总量，未证实的缓存不能宣布覆盖完成。保留原采集器的中标/成交类型 7/11 与央采代理机构范围。

输出 `request.json`、`state.json`、`records.json`、按查询隔离的 `q/`、HTTP 事件、失败原文、缓存复用来源及 SHA256。锁存在时先核实所属进程；日期范围改变必须新建任务。网络限制、目录缺失、解析错误保持失败或部分完成状态。
