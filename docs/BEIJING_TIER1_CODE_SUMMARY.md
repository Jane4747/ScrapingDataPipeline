# 北京一级医院招采代码总结

核对日期：2026-10-27。目标是采集2024年以来的医卫数智化招标、中标原始事实，输出指定7列，并保留查询、公告与字段证据。

## 实际执行与结果

本轮251家医院均完成至少6组查询：逐院1629条、专项补查28条。词表包含11组277个去重主题词，按主题组合使用，没有将277词与每家医院机械穷举。4个网页归档任务共31次页面尝试，25次成功、6次失败。主表14条公告或分包记录，较上一轮新增7条；候选与排除记录28条。14条涉及6家，正式与候选合计涉及12家，其他239家未获得可保留的公告线索。

查询次数、网页数、公告行数、采购包和独立项目数是不同口径。全名单检索完成不代表历史渠道穷尽，也不代表所有字段完整。

## 模块职责

| 文件或模块 | 职责 | 边界 |
|---|---|---|
| `scripts/tender_tools.py` | 从Excel读取名单；从已知URL生成v1采集任务和精确域名白名单；核对日期、公告阶段和金额；导出7列CSV/JSON | 不自行执行会话搜索，不自动证明事实 |
| `configs/beijing_tier1_keywords_v2.json` | 综合、诊疗、医保、患者服务、公卫、运营、数据AI、云硬件、网络、安全、智能管理词表 | 非标题必含词；混合采购需看正文及附件 |
| `run-local.ps1`、`pipeline/task_runner.py` | 任务校验、执行、状态、恢复和阶段依赖 | 先dry-run；partial保留失败，不能报告成完整 |
| `pipeline/research/` | 受域名、robots、限速和大小限制的网页/PDF采集；检查点和原文归档 | 扫描PDF无文本层时需另行读取；访问限制不绕过 |
| `scripts/tender_audit.py` | 参数化审计名单覆盖、真实查询留痕、日期/字段、汇总计数与证据路径 | 离线检查，不会新增搜索或自动补缺失字段 |
| `pipeline/idea_tree.py` | 保存id/parent/kind/at/text节点，生成Markdown想法树 | 节点完成状态须有实际证据支持 |
| `scripts/beijing_tenders.py` | 实验性门户发现、候选验证及抽取入口 | 未用于本轮检索；导出前需人工核验，不能凭网址猜日期 |

## 核验规则

- 客户标签沿用原名单，采购人名称不同不推断举办或隶属关系。
- 日期使用公告正文，不能用网址、抓取日期或编号中的数字代替。
- 招标预算、最高限价、候选报价不能填中标金额；只有折扣率、单价时总额留空。
- 非确定成交阶段不能填写中标单位或中标金额。供应商被遮挡时，可保留独立披露的成交金额。
- 跨来源去重、候选转正式须有明确核验决定；招标和结果公告分别保留。
- 主体用途不明、缺参数、日期未知等保留候选；不能靠重复请求解决事实缺口。

## 本轮编排与可移植性

本轮合并、Excel制作、超链接补写和证据打包脚本保存在本地成果目录的代码归档中。其中`merge_rerun.py`、`prepare_notice_archive.py`、`finalize_workbook.py`、`package_delivery.py`使用本轮固定目录、251家和a/b/c分组，是批次编排，不是通用命令。

通用查询审计已抽出为`tender_audit.py --input-dir --output --min-queries`，使用显式校验及非零退出码，避免`python -O`禁用assert后漏检。名单导入仍固定“03-一级医院”的列布局。`tender_tools`保留旧日期默认值以兼容历史调用，新任务必须显式传入`--since`与`--until`。

同样格式的Excel由会话环境中的`@oai/artifact-tool`生成，并完成渲染检查；普通Python环境可独立使用仓库的CSV/JSON导出，不能声称安装本仓库即可复现该专用Excel渲染器。
