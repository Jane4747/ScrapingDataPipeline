# 北京、雄安医卫数字化中标：采集设计与口径

本轮目标：把北京、雄安两地的医卫数字化中标结果，落成与央采同一张八列表——项目名称、产品、
招标单位、客户标签、中标单位、运营商类型、中标金额（万元）、场景。

代码：`pipeline/research/bjxa.py`；共用口径：`pipeline/research/bid_common.py`；
测试：`tests/test_bjxa_medical_bid.py`（29 项）；想法树：`idea-trees/20261027-bjxa-medical/`
（`scripts/write_bjxa_tree.py` 可重复执行，覆盖同一棵树）。

## 一、入口勘察（先证明能不能采，再谈怎么采）

| 入口 | 实测 | 结论 |
|---|---|---|
| `ggzyfw.beijing.gov.cn`（北京市公共资源交易服务平台） | 首页、robots.txt 均返回 403（WAF 拦截页，65KB） | **不可用**。按既定规则：遇到拒绝不绕过、不伪装浏览器 UA、不加代理、不关证书校验，只留证 |
| `www.ccgp-beijing.gov.cn` 市级「中标公告」`A002004001002index_N.htm` | 200，静态 HTML，14 条/页 | **采用**。列表项只有标题+日期，采购人/金额进详情页取 |
| 同上 区级「中标公告」`A002004002002index_N.htm` | 200，结构一致 | **采用**（北京区级项目也走同一条口径） |
| 北京列表翻页上限 | 每个频道 `TotalPage=143`；第 144 页 **404**；第 143 页最早只到 市级 2026-07-15 / 区级 2026-08-10 | 站点只保留最近约 2000 条列表。**2026 上半年不在列表可达范围**，见“缺口” |
| 北京站内检索 `/api/search/query`（历史数据查询 SPA） | 关键词查询 200，可返回 2006 年至今；但 `range` 日期过滤：ISO/纯日期/epoch 三种写法分别返回 0 条或 400，`{"before":"2026-12-31"}` 直接 400 | **不能按月补窗**，放弃用它凑上半年数据，不硬拼 |
| 北京详情页 | 200，`div.BodyLabel` 内含一、项目编号／二、项目名称／总中标成交金额／中标成交供应商名称／四、主要标的信息（商品名称·规格型号）／采购人信息 | 按标签抽取，无需猜版式 |
| `www.xaprtc.com`（雄安新区公共资源交易服务平台） | 200；交易公开→政府采购 = `queryContent[-N]-jyxx.jspx?channelId=273`，10 条/页，共 1253 页（全史 12522 条），可回溯到 2026 年初 | **采用**为雄安列表入口 |
| 雄安详情页 `/jyxxzccj/xxxxx.jhtml` | 200 但是**壳**：公告类型/交易方式/项目编号为空，正文不渲染，只有「公告来源」指向河北省政府采购网 | 必须二次取正文 |
| `www.ccgp-hebei.gov.cn` 文章页 | 目录页 403、robots.txt 403、http 偶发 502（https 正常） | **不取**（fail-closed）。正文改走同一公告在 ccgp 地方公告的镜像 |
| `search.ccgp.gov.cn/bxsearch`（补窗 + 雄安正文镜像） | 200；`timeType=6` + `start_time/end_time` 按月切窗可用 | **采用**。只收 `/zbgg/`、`/cjgg/`，北京限 `/dfgg/` |

雄安三县（雄县/容城/安新）的「公告来源」会落到不同路径：新区本级是 `/xazq/xaxq_xaxq/cggg/zhbggAAAS/`，
容城是 `/bd/bd_rc/cggg/zhbggAAAA/`。脚本不按路径区分，只取外壳页里任意 `ccgp-hebei.gov.cn/*.html`，
再按标题到检索站反查同一公告的 ccgp 页；反查不到就跳过（本轮有 4 条壳页因此无项目名被跳过，见缺口）。

## 二、采集链路

```
北京：ccgp-beijing 市级/区级「中标公告」index_N.htm（14 条/页，最多 143 页）
        ↓ 剥掉标题前缀 [公开]/[朝阳区]（存为 region_hint）
      标题级过滤：医卫主体 ∩ 数字化标的
        ↓ 逐条取详情 /xxgg/{sj|qj}xxgg/{zbggs|qjzbggs}/YYYY/MM/<hash>.htm
      抽：项目编号 / 项目名称 / 总中标成交金额 / 中标成交供应商名称 / 采购人 / 代理机构 / 主要标的
        ↓ 打标 → 八列表 + 明细页

雄安：xaprtc 政府采购 channelId=273 列表（10 条/页，50 页到底）
        ↓ 只留 /jyxxzccj/（中标·成交结果），/jyxxzccg/（采购公告）、/jyxxxqgs/（需求公示）不进表
      标题级过滤（标题自带【雄安新区xx】前缀，直接作区县字段）
        ↓ 取雄安详情壳 → 读「公告来源」→ 指向 ccgp-hebei 时按标题反查到 ccgp 地方公告页
      抽：项目名称 / 采购人 / 预算 / 供应商 · 标的 · 各包金额（ccgp 地方公告横表）
        ↓ 打标 → 八列表 + 明细页
```

- **节流与合规**：全程走 `pipeline/research/fetch.py` 的 `Fetcher`——robots 检查、单站点最小间隔、
  401/403/429 判 `blocked` 不重试不绕过、UA 自报 `CAICTMedicalResearchBot/1.0 (public-source research)`。
- **缓存优先**：列表页与详情页都落盘 `cache/<tag>-<md5>.html`，重跑命中缓存不发请求；
  `--from-cache` 只用缓存重出表（列表、详情、标题反查、按月补窗四处都受该开关控制，全程零请求）。
- **失败留痕**：每次取页失败写进 `bjxa_medical_bid.json` 的 `failures`（阶段、状态码、URL、原因）；
  被限流打断的月份写进 `supplement.stopped`，不静默跳过。

## 二之二、补窗与地域校验（两个坑都踩过）

列表页够不到更早月份时，用 `search.ccgp.gov.cn/bxsearch` 按月切窗补：`timeType=6` + `start_time/end_time`，
`page_index` 翻页，只收 `/zbgg/`（中标）与 `/cjgg/`（成交）。

补窗踩了两个坑，都在入表前挡住：

| 坑 | 现象 | 处理 |
|---|---|---|
| 中央/外省公告混入 | 北京补窗拿来中央单位的项目（应属央采口径） | 加 `path_filter="/dfgg/"` 只要地方公告 |
| 检索全文命中 ≠ 本地项目 | `雄县` 命中云南**镇**雄县；`安新` 命中浙江**磐**安新城区、营口**华**安新邨 | 三道校验：平台域名放行 → 检索结果行地域标签（空标签视为未知，交给下一步）→ 标题地名必须带行政后缀（`容城县/安新县/(?<!镇)雄县/雄安/容东/容西`） |

第三个坑更隐蔽：检索结果标题把关键词包了高亮标签，`get_text(" ")` 会把“安新县”拆成“安新 县”，
所以比对地名前先去掉空白；反过来，只按地域标签白名单过滤也不行——雄安宣武医院的公告由北京单位代发、
标签是“北京”，而雄安关键词命中的多数行标签是空，一刀切会把 5 条真项目误杀。

## 三、八列口径

与央采共用 `bid_common`，不另立一套：

| 列 | 取值 | 说明 |
|---|---|---|
| 项目名称 | 正文「项目名称」，去掉尾部「中标公告/成交公告」 | 雄安取 `PROJECTNAME` |
| 产品 | 北京取「主要标的信息」表的**商品名称**列去重前 4 项；雄安取打包串里的标的名称 | 取不到时退化为场景词，不臆造品牌型号 |
| 招标单位 | 北京取「采购人信息—名称」；雄安取 `PurchaserName` | 缺失留空，不用列表标题猜 |
| 客户标签 | 按采购人名称分层（专科优先于综合） | 与央采同一函数 |
| 中标单位 | 北京取全部「中标成交供应商名称」去重；雄安取打包串里的供应商，多包用「；」连接 | 不做股权穿透 |
| 运营商类型 | 名称含 中国移动/中移、中国电信、中国联通、中国广电 → 对应运营商 | 与央采一致 |
| 中标金额（万元） | 北京取「总中标成交金额」（亿元×10000、元÷10000）；雄安打包串给的是**分元包金额**，多包求和后折万元 | 明细页保留原文/各包金额便于复核 |
| 场景 | 标题优先，标题未命中再看标的文本，取首个命中类别 | 不做多标签打分 |

**雄安金额口径差异**：河北政采正文不给“总中标成交金额”，只给每个包的金额（元）。本表按“各包金额求和”
折算万元，并在明细页保留 `各包金额（元）` 原文；单包项目与公告口径一致。

## 四、明确不覆盖的范围

1. 北京 2026-04~07 月：平台列表被站点截断在 143 页（2000 条，市级最早 2026-07-15、区级 2026-08-10），
   站内检索的日期过滤实测失效，改用 ccgp 按月补窗；1–3 月补齐，但 4–7 月补窗被检索站限流判 `blocked`
   （`supplement.stopped` 有 10 条记录）。这段**没有**用不可靠的方式凑数。
2. 北京市公共资源交易服务平台（ggzyfw）本体：403 拦截，未绕过。北京侧数据实际来自
   北京市政府采购网（同属北京市财政局政府采购信息公开渠道，北京市政府采购中心项目也在其中）。
3. 雄安工程建设类交易（`/jyxxgc*/`）：不属于政府采购中标结果，不进表。
4. 更正公告可能改金额：只取结果公告，金额以公告原文为准；合同变更、追加、结算未纳入。
5. 项目“是否落地/验收”不做推断，公告只证明中标事实。

## 五、复现

```bash
# 两地全量（列表 + 详情 + 补窗 + 出表）
python -m pipeline.research.bjxa --start 2026-01-01 --end 2026-10-27 \
    --output outputs/bjxa-medical-2026/run1 --delay 5.0

# 只用已落盘缓存重出表（零请求，约 15 秒）
python -m pipeline.research.bjxa --from-cache --output outputs/bjxa-medical-2026/run5

# 只看列表与过滤，不取详情
python -m pipeline.research.bjxa --dry-run --max-pages-bj 20 --max-pages-xa 50

# 不跑补窗，只用平台列表
python -m pipeline.research.bjxa --no-supplement
```

输出：`北京/北京医卫数字化中标_2026.xlsx`、`雄安/雄安医卫数字化中标_2026.xlsx`（主表八列 + 明细页），
同名 CSV（UTF-8 BOM），`口径边界复核.csv`（见第六节），以及 `bjxa_medical_bid.json`
（逐条记录、排除项与原因、失败台账、补窗统计、运行日志）。

### 口径边界：北京 42 条 / 34,015.50 万元（占 50.8%），雄安 3 条 / 1,774.13 万元

`bid_common` 的 `DIGITAL`/`NON_DIGITAL` 是央采那一轮定下的，对“设备维保、设备带量采购、空调净化、
检验委外、医疗设备包”这几类放得偏宽。本轮用 `boundary_hint()` 把它们标出来，单列 `口径边界复核.csv`：

| 类别 | 北京 | 雄安 | 判据 |
|---|---|---|---|
| 医工设备维保 | 23 | 0 | 医用/放射/CT/核磁/超声/内镜/直线加速器/显微镜/监护… + 维保/保修/维修 |
| 医用设备购置 | 11 | 3 | 带量采购、医用设备集中、医疗设备采购/购置、科研设备购置；以及裸“医疗设备/医用设备”（后面不接管理/信息/系统/平台/数据/软件/网络/运维/监控） |
| 后勤设施维保 | 5 | 0 | 空调/净化/电梯/锅炉/污水处理/物流/被服/食堂 + 维保/运行/服务 |
| 检验病理委外 | 2 | 0 | 委外/外送/委托 + 检测/检验/病理 |
| 非数字化物资 | 1 | 0 | 农副产品、食材配送 |

剔除后的口径内合计：北京 **97 条 / 32,894.81 万元**、雄安 **5 条 / 7,245.92 万元**
（`summary.amount_wan_ex_boundary`）。

**没有直接改共享口径的原因**：`DIGITAL`/`NON_DIGITAL` 同时被央采使用，一改央采那张已交付的 109 条表
也会跟着变。所以本轮只标不改，等确认影响面后再统一收紧并重出三张表。判定 IT 类维保（存储、网络、HIS）
与“医疗设备管理系统”不会被误伤——边界规则只认医工硬件与后勤设施词，且对“医疗设备+系统/平台/数据”做了排除。
