# 养老院补查（p7/p8/p9）方法论与字段规范

本文件供本次补查子任务（p7/p8/p9，共 54 家）统一口径。目标：完成养老/护理/医养类机构
的官网、官方公众号、联系方式与 2023–2026 医卫数字化报道补查，输出符合既定 schema 的 JSON。

## 一、采集纪律（务必遵守）

1. **不推断公众号名**：仅当检索结果（官网/民政公示/报道正文）明确写明"XX 是该机构官方微信公众号"
   时才录公众号名；只出现"已开通公众号"但无名称 → 留空，并在公众号来源/备注说明。
2. **官网认定严格**：仅认机构**自有独立域名**官网（如 xxx.com / xxx.cn）。以下**不算官网**，不得填入"官网"字段：
   - 第三方养老平台（如安养帮、养老信息网、开心养老网等）
   - 地图/百科/企查查/天眼查/民政公示页/招投标平台页
   - 母体医院/上级集团域名，除非该域名下明确有本机构专页且可代表本机构
3. **缺口留空**：电话、地址、金额、评审专家、资格要求等查不到即填 `""`（空字符串），严禁编造/推断。
4. **时间范围**：报道/项目仅取 2023–2026（含 2026 当年）。
5. **来源类型**归一为 9 类之一：公众号原文 / 官网新闻 / 媒体转载 / 采购公告 / 中标公告 / 学术 /
   财政 / 行业会议 / 民政公示。
6. 若多次检索确无结果，采集状态填"已查询-无独立官网"（机构类机构无官网为常态），不得填"检索失败"
   除非确实因网络/限流无法检索。

## 二、输出文件与顶层结构

为每个批次输出一个 JSON：`configs/agedcare_reports_pN.json`（N=7/8/9），结构：

```json
{
  "批次": 7,
  "任务": "养老院补查",
  "入口任务ID": "agedcare-full-20261101",
  "抓取时间": "2026-11-02",
  "采集来源": "WebSearch",
  "说明": "养老类机构官网/公众号/联系方式补查 + 医卫数字化报道分析(表A) + 明确项目(表B)。缺口留空，不推断。",
  "failed": [],
  "institutions": [ ... 18 条 ... ],
  "reports": [ ... 若干条 ... ],
  "projects": [ ... 若干条 ... ]
}
```

`institutions` 必须**恰好 18 条**（对应本批次目标清单全部机构，逐一补查，0 失败）；
`reports` 为报道（表A）列表；`projects` 为明确项目（表B）列表，可为空。

## 三、institutions 字段（共 16 列，每条必填）

| 字段 | 说明 |
|---|---|
| 机构ID | 取自目标清单（如 ORG-0421） |
| 机构全称 | 取自目标清单 |
| 省份 | 取自目标清单 |
| 城市 | 取自目标清单（可能为 null → 填 ""） |
| 出现表 | "远程协同试点" |
| 机构类型 | 取自目标清单 |
| 疑似重复组 | 取自目标清单（无则 ""） |
| 官网 | 自有独立域名；无则 "" |
| 官网来源 | 官网出处说明；无则 "" |
| 官网可达性 | 一律填 "未校验" |
| 微信公众号 | 仅明确标注的官方公众号名；否则 "" |
| 公众号来源 | 出处说明；无则 "" |
| 联系电话 | 查到的电话；无则 "" |
| 地址 | 查到的地址；无则 "" |
| 采集状态 | "已查询-有官网" / "已查询-仅公众号" / "已查询-无独立官网" |
| 备注 | 自由备注（母体关系、资质、其他电话等）；可空 |

## 四、reports 字段（共 15 列，表A 报道）

| 字段 | 说明 |
|---|---|
| 机构名称 | 机构全称 |
| 机构ID | 对应 ID |
| 省份 | 省份 |
| 公众号 | 该报道发布公众号（若是公众号原文）；否则 "" |
| 报道标题 | 标题 |
| 来源类型 | 9 类归一之一 |
| 来源链接 | URL |
| 发布时间 | YYYY-MM-DD 或 YYYY-MM |
| 响应政策 | 关联的医卫数字化政策要点（如"医养结合""互联网+医疗健康""远程医疗"等） |
| 内容总结 | 1–2 句概括 |
| 技术支持机构 | 有则填；否则 "" |
| 资金支持机构 | 有则填；否则 "" |
| 目的与结果 | 该举措/项目的目的与成效 |
| 是否明确项目 | "是（采购/中标项目）" / "是（战略合作/医共体）" / "否（服务型举措）" |
| 备注 | 自由备注；可空 |

## 五、projects 字段（共 43 列，表B 明确项目）

沿用医院表B字段。关键填充规则：
- `机构名称` / `医院名称` = 机构全称；`机构ID` / `医院ID` = 对应 ID
- `省份` = 省份；`客户标签` = 机构类型（如 护理院/养老机构/医养结合机构）；`批次` = N；`来源文件` = agedcare_reports_pN.json
- `公众号` = 报道发布公众号（若是公众号来源）；`来源链接`/`网址` = URL；`时间` = 发布时间；`项目名称` = 项目名
- `公告类型` = 自由文本原始类型，如"采购公告""中标公告""战略合作签约"等；脚本会再归一为"公告类型_归一"
- `数字化标签` = 若确为信息化/数字化采购项目填"是"，否则填"否（原因）"
- 采购/中标类才填 `中标单位`/`中标金额万元`/`评审专家`/`响应人资格要求` 等；战略合作/医共体类这些留空，且在 `信息缺口` 注明"非采购类项目，无…"
- 其余未提及字段一律填 ""（空字符串），保持 43 列完整

## 六、工作流建议

1. 逐机构 WebSearch：机构名 + "官网"/"公众号"/"联系电话"/"地址"/"医养数字化"/"智慧养老"/"远程医疗"。
2. 判断官网/公众号是否符合纪律 → 填 institutions。
3. 收集 2023–2026 医卫数字化相关报道 → 填 reports；明显是采购/中标/战略合作的 → 同时填 projects。
4. 最后一次性把完整 JSON 写入 `configs/agedcare_reports_pN.json`（用 Write 工具，确保 JSON 合法）。
5. 自检：institutions 是否 18 条、字段是否齐全、空值是否用 "" 而非 null。

参考成品：`configs/agedcare_reports_p1.json`（同 schema，可作格式范例）。
